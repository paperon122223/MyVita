## Corrección del manejo de sesión inválida

- AuthService comparte las renovaciones concurrentes y descarta respuestas de renovación si comenzó un nuevo login o logout.
- Las rutas de autenticación ya no intentan renovar una sesión ante un rechazo de login, registro o logout.
- Un 401 de renovación retira las credenciales inválidas y avisa a navegación para mostrar el acceso. Conserva identidad local y SQLite. Los fallos de red conservan las credenciales.
- 25 pruebas de la app aprobadas y TypeScript sin errores. APK release arm64 recompilado e instalado con éxito. Arranque en frío correcto (2840 ms); se confirmó visualmente la pantalla de acceso después de la detección de la sesión inválida.
- Falta que el usuario introduzca sus credenciales en el teléfono para obtener una sesión nueva y validar la sincronización. No se puede regenerar una credencial invalidada sin autenticación.

### Backend local

En el repositorio anidado `files_context/backend/myvita-backend`, `routes/auth.js` compartía un cliente Supabase entre solicitudes. La dependencia instalada activa por defecto persistencia y renovación automática; en Node inicia el temporizador de renovación. Esto permite rotaciones que no se entregan al teléfono, pero no demuestra el origen del rechazo observado en producción.

Se cambió autenticación para crear clientes por solicitud sin persistencia ni renovación automática y se desactivaron esas opciones en el cliente anónimo de OAuth. La prueba `node --test tests/auth-session.test.cjs` verifica dos renovaciones concurrentes aisladas y sus respuestas correspondientes; pasó. Ambos archivos pasan `node --check`.

Esta corrección del backend está solamente en el repositorio local. No hay CLI Railway o GitHub disponible en PATH ni herramienta de despliegue conectada; no se desplegó ni se modificó el servidor remoto.
